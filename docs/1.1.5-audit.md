# 1.1.5 可靠性、体验与性能审查

日期：2026-09-07。范围：下载面板、分 P/列表队列、下载与保存、合成。源码开发验收版，不代表商店通过或所有设备验收通过。

## 设计结论

依据用户的「都市直觉」参考图、反馈截图，以及连接 Edge 中实际捕获的 1.1.2 面板（BV14H7y6mE6m，P5）。实际面板结构紧凑，品牌图标明确；长标题和分 P 按钮会增加滚动，底部支持入口需要滚动才能完整看见。

适合局部借鉴，不适合整套照搬。可以考虑暖白背景、深蓝主操作、红色仅表示危险；保留蓝色产品图标、系统无衬线字体、已有控件位置。不引入纸纹、装饰卡片、大衬线标题、外部字体或额外动画。换皮不是解决下载反馈的前提，本轮不做全量重设计。

本轮提高浅色辅助文字对比度，支持减少动态效果的系统偏好；状态提示有辅助技术语义。不是完整 WCAG 认证。用户此前要求隐藏的历史、诊断、策略入口未重新展示。

## 已修问题

1. 双轨暂停时共享 Promise，避免后等待的音轨覆盖视频的恢复回调；取消/失败释放等待者。
2. 暂停不再发送取消合成；取消才真正终止 Worker。合成阶段不冒充可暂停。
3. 暂停期间等待后再发起下载。分 P 队列锁定启动时的 URL，列表解析后由统一启动入口再检查暂停/取消。
4. CDN 忽略续传 Range 时丢弃原有分片重新接收；校验返回范围和可见总长度，拒绝已知截断。
5. MP4 / M4A 不再靠 anchor.click 和固定 1 秒/5 秒计时推断保存完成。使用浏览器下载管理器，确认 complete 才继续队列；中断报错；只有保存进行中每秒查询一次，没有新增闲时轮询。
6. 保存中保留取消按钮；成功提示提供浏览器下载记录入口，不额外要求通知权限。
7. 不再把旧格式多段视频的第一段命名为完整 MP4；非 MP4 容器明确报错。不再把音轨失败降为“成功下载无声 M4S”。
8. 同清晰度优先 AVC，音频优先 AAC。去除将当前播放器其他视频的嗅探流作为任务备用流的路径。
9. 合成前扫描小段 box 头，校验片段/索引数量与边界，不读整份文件进 ArrayBuffer。大文件 Worker 不可用时不回退主线程。
10. CDN 两字节探测拿到响应后立即中断，避免服务器忽略 Range 时继续消耗整份媒体带宽。

原生下载接口依据：[Chrome downloads](https://developer.chrome.com/docs/extensions/reference/api/downloads)、[Mozilla DownloadItem](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/downloads/DownloadItem)。后台验证消息来源、Blob 同源、文件名及下载所属扩展；不向内容脚本暴露用户其他下载记录。

## 本地证据

- `node --test test/download-runtime.test.mjs test/*regression.test.mjs`：动态下载/保存/权限/封装用例与既有布局结构检查。
- `node test/merge-local.mjs`：仅使用本地已有视频轨 67,555,679 字节、音轨 6,260,989 字节，无网络下载、无上传。
- 输出 73,808,815 字节；本机运行约 1.0–1.2 秒，输出为 H.264 + AAC，时长 663 秒（音轨约 662.976 秒）。FFmpeg 整文件解码到 null，无错误，未覆盖 QuickTime 真机。
- Node 主线程心跳仍运行，但包含文件读取、Blob 构建和结果写盘的最大间隔约 63–109ms。这不是浏览器帧率指标，不能据此声称页面完全无影响。
- 语法检查与 `git diff --check`。既有商店素材删除/修改不属于此次改动，不提交。

## 未闭环事项与明确限制

- 浏览器现场仍是 1.1.2；本轮 1.1.5 需用户重载后真实下载验收，尤其是原生 Blob 保存与 Firefox。
- macOS「仅预览 5 秒」没有用户原始文件，未复现。已修相关风险并验证已有样本，不等于已确认反馈根因。
- BV1Dg4y187bZ 的 60 分 P 全量成功率尚未验收。顺序队列不能解决服务端限流、权限或片源本身缺失；不能保证每个视频都能下。
- 2GB 以上真实媒体、低内存设备、前后台切换、Mac QuickTime、Firefox 需单独验收。无硬编码文件大小拒绝不代表内存无限。
- 当前合成器要求带索引的普通分片 MP4；不支持的封装会明确失败，未来可替换更通用且可测试的 remux 引擎，而不是强行保存坏文件。
- 页面刷新/关闭会终止尚未保存的页面任务；没有宣称跨页面断点续传。跨标签全局调度、持久队列和磁盘流式写入属于后续架构工作。
- 远程公告配置仍按用户决定使用 HTTP；本轮没有改变服务、权限或部署，HTTP 的安全风险仍存在。

## 重载后验收顺序

1. 短视频 MP4、M4A：保存完成、浏览器记录、文件大小、首尾播放；模拟取消保存，不能显示成功。
2. 双轨下载：反复暂停/继续、取消；没有卡死、没有后台残留下载。
3. 多分 P：一键自动顺序、暂停全部、继续全部、取消全部；队列中切换当前播放分 P，不得改写任务来源。
4. 大文件合成时滚动页面、操作播放器、关闭/打开浮窗；记录 Long Task 和内存，不只看进度条。
5. 原用户失败分 P 和 macOS 文件复测；获得这部分证据之前不要发布“反馈已全部解决”的公告。
